TWO-DOC STRUCTURE (ratified by Riley 2026-07-13): `docs/SESSION_HANDOFF.md` is the RESUME doc (header, recent session blocks, batch map, Open queue, cosmetics); `docs/SESSION_REFERENCE.md` holds the STANDING sections (ground-truth check, gates, How to work, persona, sequencing, moat thinking, casebook rules, integrity-first, campaign state, archived-findings pointers) and is updated IN PLACE in the same commit as the decision that changes it — standing sections do NOT move to the archive unless genuinely superseded.

WRITE-TIME RULES (prevention, added 2026-07-10 — these apply whenever SESSION_HANDOFF.md is UPDATED, not just when pruning; they keep the doc from needing big prunes):

- A. **Tombstone at closure.** When a commit closes an open-queue item, the SAME commit rewrites the item to its one-line ~~struck~~ tombstone (what closed it, commit hash/CB ID, "Full record: ..."), with the full original text moved to the archive then or at the next prune. Same discipline as casebook entries shipping in the same commit as their enforcement change.
- B. **Cite, don't restate.** A new session block gives one line + pointer for anything that has a canonical home — casebook entries, CLAUDE.md definitions, audit docs, runbooks, commit messages. Full narrative belongs in those homes, not the handoff.
- C. **One summary, not two.** When a new session block is written, the `Last updated` header paragraph is REWRITTEN to summarize only the new state (target ≤150 words) — the outgoing header paragraph is replaced, its text preserved in the archive if it contains anything its own session block doesn't (precedent: the "[archived] Original 'Last updated' header paragraph" sections).
- D. **The ceilings are machine-enforced.** `tests/test_handoff_size.py` fails the suite past 80,000 bytes (resume) / 60,000 bytes (reference); the fix is this command (resume) or in-place tightening with superseded text archived (reference), never deleting content or casually raising a ceiling.

RULES (all mandatory, in order):

1. **Faithful Transcription.** Every moved block is verbatim, byte-identical. Never reword, summarize, or "fix" content while moving. If something in a block looks wrong, flag it in the completion report — do not silently correct it.
2. **Extract before you move.** Scan each block being archived for anything STILL OPEN — open sub-items, watch notes, standing rules whose only copy lives in that block. Extract those into the Open queue (or the appropriate standing section) FIRST, each labeled "(extracted at archive time from <block>)". State per block what was extracted, or explicitly "nothing open" — silence is not acceptable.
3. **What stays in the resume doc:** the `Last updated` header; the most recent 1–2 session blocks; the batch map; the Open queue (open items + one-line tombstones); the known cosmetic/minor list. (Since the 2026-07-13 split, the standing sections — ground-truth check, gates, How to work, persona, sequencing, moat thinking, casebook, integrity-first, campaign state — live in `docs/SESSION_REFERENCE.md`, out of the prune's scope.)
4. **What moves:** session blocks older than the most recent 1–2 (leave one pointer line where they sat); closed open-queue items still carried at full length (leave a one-line ~~struck~~ tombstone: what closed it, commit hash(es)/CB ID, and "Full record: SESSION_HANDOFF_ARCHIVE.md"); fully-closed slot records and findings sections (leave a one-line pointer, following the Suncor-slot precedent).
5. **Archive format:** append to `docs/SESSION_HANDOFF_ARCHIVE.md` under `## [archived] <descriptive title>` headers — the headers are labeled organizational ADDITIONS; all content beneath each header is verbatim. Add a dated HTML comment noting the archive-time date/commit, matching the existing file header's pattern.
6. **Machine-verify the move.** Script a check (do not eyeball): every non-blank line removed from SESSION_HANDOFF.md must appear verbatim in SESSION_HANDOFF_ARCHIVE.md. Report the check's result. Preserve the files' existing line endings (both are CRLF as of 2026-07-10).
7. **Archive-time closures.** An item overtaken by shipped work but never struck may be tombstoned, but the tombstone must say "closure graded/recorded at archive time (<date>)" and the completion report must list every such grading for Riley's veto — the prune must never silently decide a closure.
8. **Completion report:** list every block moved, every extraction made, every archive-time closure graded, any content flagged as looking wrong, and the verification result. Commit message pattern: `docs(handoff): prune — move closed items + historical session blocks verbatim to SESSION_HANDOFF_ARCHIVE.md`.
